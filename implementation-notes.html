同步补丁的结尾换行规范化

状态：agent-resolved

日期：2026-07-12

背景：overrides.yaml 中使用 YAML block scalar（text: |）定义的 append_content 文本自带结尾换行；补丁引擎此前又无条件追加一个换行，导致强制同步审计生成仅多一个尾部空行的差异，并错误触发 plugin 版本升级和 PR。

决策：append_content 在拼接前对补丁文本执行 trimEnd()，最终统一保留一个文件结尾换行。该规范只消除补丁配置携带的尾部空白，不改变正文内部空白。

验证：tests/patch-engine.test.ts 覆盖带结尾换行的 YAML block scalar；同步 Action run 29180216479 重新审计后，原误报的 docs-vs-code、docs-vs-docs、geju、goudi、idea、razor、web 均报告“文件内容无变化”。

Skill 分发载荷精简规则

状态：user-decided

日期：2026-07-22

背景：上游同步会把开发测试、已渲染 golden、仓库门面文档和未接入主执行路径的参考资料一并带入 plugin；直接删除会在后续同步时恢复。

决策：通过 overrides.yaml 的 exclude_files 永久屏蔽 archify 测试与 rendered HTML、kami 测试/发版/MCP 脚本、无用 README 和 .gitignore、goal-gen manifest、六份不可达的 pua 高阶参考，以及 hai 系列的 SKILL.zh_CN.md。保留各平台 agent metadata、xiaohei 示例图、web worked example、teach glossary 和所有许可证文件。

实现约束：exclude_files 中以 / 结尾的规则按目录前缀匹配，以便持续屏蔽后续新增的同类文件；被排除文件不得继续作为 target_patches 目标，并须从 .sync-state.json 的文件清单移除。布局测试持续验证排除规则、同步状态与发布目录一致。

决策来源：用户明确选择上述保留与删除范围，并要求所有删除通过同步规则屏蔽，避免后续同步重新带回。

上游删除段落导致 replace 补丁长期失效

状态：agent-resolved

日期：2026-07-26

背景：tw93/Waza 上游已删除 read/ui 的 “Update check (non-blocking).” 段落，但 overrides.yaml 仍配置对应 replace 补丁。补丁匹配失败使每日同步持续产出 [补丁失败] 草稿 PR（#148/#150/#151），真实内容更新被挡在草稿态无人合并。

决策：删除 read/ui 两处已失效的 replace 补丁，保留 exclude_files: scripts/check-update.sh（上游若恢复该脚本仍需屏蔽）。kami 的同类补丁保留，因为其上游 scripts/check-update.sh 与 SKILL.md 段落仍存在。重新执行 npx tsx scripts/sync.ts --force 生成非草稿 PR #153/#154。

实现约束：同步脚本按 upstream SHA 命名分支，被取代的旧 SHA PR（#147/#148）需人工关闭；关闭 PR 后 --force 重跑才会重建分支。重跑生成的 PR 基于旧 main，若期间 main 已递增同一 plugin 版本，需 rebase 后手工把版本号继续 +0.0.1 并重新 build:marketplace（本次 creative 0.0.11 → 0.0.12）。

验证：npm test（45 passed）；合并后分支 SKILL.md 中 “update check” 匹配数为 0；PR #153/#154/#155 均以 MERGEABLE/CLEAN 合并。

archify 2.12 上游改版导致三处补丁失效

状态：agent-resolved

日期：2026-07-28

背景：tt-a1i/archify 在 3b5035f 把 SKILL.md 从 423 行精简为 103 行并新增 references/ 三份文档，同时把 package.json 的 test 脚本从 node --test test/*.test.mjs 改为 node ../scripts/run-tests.mjs。overrides.yaml 的两处 SKILL.md replace_all 目标段落已被上游整体删除，package.json 补丁则因脚本值变化而无法匹配，同步产出 [补丁失败] 草稿 PR #156，并把引用 test/ 的脚本带进发布载荷。
